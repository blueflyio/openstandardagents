# Academia, Education, and Policy Research (2025-2026)

## Cornell (eCornell): Agentic AI training pipeline

Cornell’s eCornell offerings frame agentic AI as a progression from:

1. LLM intuition/prompting,
2. RAG/context engineering,
3. tool+memory agent architectures (including MCP),
4. governance/risk/ethics for deployment.[R46][R47]

Key takeaway: the curriculum explicitly combines technical build skills with governance and human oversight, not just model usage.[R46]

## Harvard: protocol-centric governance lens

Harvard Library Innovation Lab’s Agent Protocols Tech Tree (APTT) treats open protocols as the key coordination mechanism for a decentralized agent ecosystem.[R48][R49] The framing parallels early internet protocol evolution (TCP/IP, DNS, HTTP) and argues that protocol choices can shape which agent behaviors are easy/hard to deploy at scale.[R48]

Related legal/policy commentary (Harvard JOLT digest) emphasizes a governance fork:

- platform-governed agent activity (walled ecosystems), vs.
- interoperable protocol-governed agency (portable identity/delegation/accountability).[R62]

## MIT: deployment acceleration + transparency warning

### MIT AI Agent Index (2025 edition)

The MIT AI Agent Index documents 30 deployed systems and highlights:

- rapid release cadence,
- rising autonomy,
- substantial disclosure gaps for safety testing and evaluations,
- unresolved standards for web conduct and attribution.[R50][R51][R52]

The "further details" methodology (public-source coding, review process, developer feedback loops) makes it one of the most operationally useful cross-agent baselines currently available.[R51]

### MIT Sloan

MIT Sloan’s 2026 guidance describes agentic AI as strategically important but "not ready for prime time" in many contexts due to hallucinations and security risks (including prompt injection), while still forecasting major medium-term adoption in enterprise processes.[R53][R54]

Practical stance: start capability building now, but include risk management, governance, and socio-technical integration as first-order work items.[R53][R54]

## NIST/NCCoE: identity and authorization as core control problem

NCCoE’s concept paper calls for focused work on software/AI agent identity, authorization, audit, non-repudiation, and prompt-injection-aware controls.[R55]

This matters because many enterprise IAM models were designed for humans or static services, not adaptive autonomous actors with delegated authority.[R55]

## Research Gaps Observed

1. **Limited standardized reporting** for safety evaluations across commercial agents (confirmed by MIT Index findings).[R51]
2. **Weak cross-paper comparability** for protocol and framework claims (different benchmarks/metrics).
3. **More security research than security operations evidence**: many papers identify vulnerabilities, fewer publish long-run production controls and outcomes.
4. **Policy-to-implementation gap**: governance principles are clear, but identity/delegation/audit implementations are fragmented across vendors and stacks.
